# A1 최대 지속 부하의 평균·tail latency

2026-10-17.4 Die ×2 Pseudo Channel ×8Plane, 총64Plane의 영역별 배치에서 A1의4KiB 연속 읽기를 지속 공급했다.4개 Host Port 모두 항상 다음 요청을 준비하며 장치 QD/버퍼 조건이 수락을 제어한다. QD512/Port, 공유8MiB, PF OFF, CA FIFO, round-robin,85% 가용률, seed7, 기존 tR를 유지했다. 같은 Die의 두 PC는 CA·Data가 각각 독립이며 Die 공통 제한은 없다. CA·Data 독립 조건은2026-10-17 사용자가 확인했다.

## 지연 정의와 부하

주 지표는 요청 수락(accepted AR)부터4KiB의 마지막 Host 데이터 반환 완료까지의 시간이다. 이는 순수 NAND tR나 실제 UCIe end-to-end 지연이 아니다. response 시작 지연은 r_start−accepted로 별도 기록한다. 제공 시각 offer는 포트당 하나의 pending 요청을 유지하는 생성기의 시각이며 임의의 상위 소프트웨어 큐 대기를 표현하지 않는다.

초기200µs 뒤200–2200µs 사이 수락된 요청을 cohort로 삼는다. 시뮬레이터는 부하를 줄이지 않고2500µs까지 계속 공급한다. 종료 구간을 넘어 완료되는 cohort 요청도 모두 포함하고 미완료 요청이 있으면 통계 생성을 거부한다. 시뮬레이터 절대 시작은30µs이므로 원시 CSV의 수락 범위는[230,2230)µs다.

최대 부하는 현재 Host 상한256GB/s에 도달하는 지속 부하를 뜻한다. QD 자체를 무제한으로 키운 조건이 아니며 설정 QD는512/Port다. 두 대역폭 조건 모두 측정 구간의 처리량256GB/s, Port별64GB/s를 유지하고 이전의88개25µs 구간과 정확히 일치했다.

## 평균 지연 분해

| 구간 | 40.05625GB/s/PC | 80.1125GB/s/PC |
| --- | --- | --- |
| 수락 → lookup 시작 | 0.001207 | 0.000849 |
| lookup 처리 | 0.500000 | 0.500000 |
| lookup 완료 → 데이터 준비 | 6.829262 | 4.485599 |
| 데이터 준비 → 응답 시작 | 23.886611 | 26.051541 |
| 4KiB Host 전송 | 0.064000 | 0.064000 |

데이터 준비 이후의 대기는 Port 내부 in-order와 Host 반환 경로 대기를 포함한다. lookup 완료부터 ready까지는 CA 대기·sensing·Data 경로·ECC 등을 포함하므로 순수 tR로 해석하지 않는다. 위 평균 분해는 합산하면 평균 전체 지연이 되지만 각 구간의 percentile을 더해 전체 percentile을 만들면 안 된다.

## 표본 경계와 검증

기준 조건에서 124,990개 요청을 집계했다. 그중 1,956개는 cohort 수락 구간이 끝난 뒤 완료됐다. 마지막 cohort 요청 완료는 부하 시작 기준 2232.118347µs이며2500µs 관측 종료보다 빠르다. 미완료 표본은0개다.

- 109개 모델·회귀 테스트 통과. 신규4개는 nearest-rank quantile, 반개구간 cohort, 늦은 완료 포함 및 미완료 거부, 지연 분해·Port 집계를 검증했다.
- 요청별CSV를 재독출하여 평균·quantile·분해·Port별 통계를 다시 계산했고 result.json과 일치했다.
- 기존 최대 처리량88개 시간 구간과 정확히 일치했다. 부하·스케줄러·장치 모델은 변경하지 않았다.
- 지연 분해 평균 합계와 전체 평균이 일치한다. Little 법칙의 시간창 outstanding/완료율과 cohort 평균도 교차 확인했다. 서로 다른 경계 표본이므로 두 값의 작은 차이는 허용한다.
- 전반/후반1ms cohort 및 초기200µs 통계도 result.json에 별도 저장했다. 주 표에는 초기 구간을 섞지 않았다.
