**명칭 안내:** 이 문서의 기존 B1/B2/B3(또는 B-1/B-2/B-3)는 현재 C1/C2/C3에 해당합니다. 새 B는 페이지 내부 64B 연속 읽기입니다. [현재 정의](15_workload_naming_ko.md)를 참고하세요. 원문 질의·과거 재현 명령은 당시 표기를 유지합니다.

## 내부 모델 설계에서 결정할 내용

- [ ] 각 port가 하나의 순서 그룹인지, 여러 ID를 독립 반환하는지 결정.
- [ ] 내부에서 port를 합치는 지점이 있다면 식별자 변환 규칙 명시.
- [ ] 물리 page 식별자와 요청 순번 분리.
- [ ] 알려진 demand 조기 실행 기준선 추가 여부 결정.
- [ ] Page 수명·교체·버전·병합 계약 확정.
- [ ] 요청 도착 시점과 AR 수락 시점 모두 기록.
- [ ] 평균 처리량, 개별 지연, tail, 내부 낭비를 평가 목표로 분리.

## 최소 실험표 제안

| 축 | 최소 비교 조건 |
|---|---|
| Trace | A-1, A-2, B-1, B-2, B-3 |
| 시작 상태 | Cold / 이전 demand 데이터 잔존 / 사전 준비 |
| 배치 | 같은 bank / 다른 bank / 다른 die / 다른 channel |
| 발행 | 직렬 / 일정 간격 / 제한된 outstanding |
| 순서 | Port별 단일 순서 그룹 / port 내부 ID별 순서 그룹 |
| 소비 | 페이지 전체 / 64B 하나 / 여러 offset / 재방문 |
| Prefetch | OFF / 알려진 demand 조기 발행 / 합성 예측 / 인과적 예측 |

조합 전체를 한 번에 실행하기보다 한 축씩 바꿔 원인을 확인합니다. 이 표는 실험 제안이며 측정 결과가 아닙니다.
